# 洗车贴膜会员系统 · UI 规范

## 产品定位

- **车主端小程序**：让车主在 30 秒内预约洗车、精洗、养护或贴膜，并随时查到车辆和施工档案。
- **店长端工作台**：让店长先看今天的预约和收款，再处理会员、结算、车辆与贴膜施工记录。

## 视觉语言

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 深海蓝 | `#073B4C` | 品牌底色、标题、深色数据卡 |
| 泡沫青 | `#0FA3B1` | 主操作、已确认状态、焦点 |
| 雾白 | `#F3FBFC` | 页面底色 |
| 打蜡橙 | `#FFB45B` | 预约主按钮与需注意的行动 |
| 预约绿 | `#087D87` | 预约成功、正常状态 |
| 待处理金 | `#C97719` | 待确认、线下待处理 |

圆角采用 12px（输入和按钮）、18px（数据卡）、22px（内容分区）；不要使用渐变、玻璃拟态和与业务无关的装饰图形。唯一的品牌装饰是深海蓝区域中的同心“水波纹”，代表洗车的水流与车辆护理。

## 车主端信息架构

1. 首页首屏：一句品牌承诺 + “去预约”唯一主操作。
2. 登录后：会员余额、预约、爱车、账单、贴膜档案四个高频入口。
3. 预约：服务、车辆、日期、时间四步，提交后明确告知“门店确认后为您预留工位”。
4. 服务档案：贴膜品牌、型号、位置、照片、质保期；避免与洗车流水混在一起。

## 店长端信息架构

1. 今日门店工作：会员数、今日充值、今日消费、运行状态。
2. 预约工作台：默认待确认，操作只显示当前状态允许的“确认 / 完工 / 取消”。
3. 查询会员：把新会员创建留在手机号查询附近，减少跳转。
4. 会员操作：充值、结算、车辆、贴膜四个流程采用同一标签导航。
5. 店长管理：员工、项目与参考价、公告、流水；项目参考价在结算时自动带入，但可修改实收金额。

## 交互底线

- 所有可点元素至少 44px；相邻触点至少留 8px。
- 主操作单屏只保留一个，并显示处理中、成功或错误结果。
- 状态不用只靠颜色：始终同时显示“待确认 / 已确认 / 已完成 / 已取消”文字。
- 表单使用明确标签；手机号和金额唤起数字键盘。
