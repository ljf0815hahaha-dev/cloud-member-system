# 正式环境真机测试清单

> 在独立测试会员、测试员工和可回滚的测试金额上执行。每项记录设备、系统、微信版本、操作人、时间、结果和关联流水 ID。不得在本地 `devMode` 下代替正式环境验收。

## 1. 设备与身份矩阵

| 端 | 身份/设备 | 最低覆盖 |
|---|---|---|
| 微信小程序 | 未授权顾客 | Android 真机、iOS 真机各 1 台 |
| 微信小程序 | 已授权顾客 | Android 真机、iOS 真机各 1 台，同一会员复登 |
| H5 | 店员 | 微信内浏览器或门店实际浏览器 |
| H5 | 店长 | 微信内浏览器或门店实际浏览器 |
| H5 | 失效会话账号 | 过期、停用、改角色、改密码各覆盖一次 |

## 2. 顾客手机号授权

- [ ] 首次进入未授权时不显示其他会员的余额、车辆、流水或贴膜档案。
- [ ] 用户拒绝手机号授权时给出可理解提示，不创建错误会员数据。
- [ ] 用户同意手机号授权后，以微信提供的手机号完成登录，不接受手输手机号冒充。
- [ ] 新手机号首次授权只创建一个 `users` 文档，`balance` 初始为 0，`openid` 与 `mobile` 唯一。
- [ ] 已存在手机号首次绑定当前 `OPENID` 时复用原会员，不重复创建余额账户。
- [ ] 同一微信账号重复进入不会重复创建会员。
- [ ] 已禁用会员无法读取会员资料。
- [ ] 页面“退出/隐藏会员信息”行为与产品提示一致；正式模式重新进入会按 `OPENID` 恢复会员，不能误称为可撤销服务端会话。

## 3. 公告有图/无图

- [ ] 无图公告可创建、显示标题，不出现破图占位或布局空洞。
- [ ] 有图公告上传成功，云存储文件可由小程序真机加载。
- [ ] 公告标题、图片、排序、启停修改后，小程序展示顺序和状态正确。
- [ ] 停用公告不再出现在顾客端。
- [ ] 非图片、超大文件和不支持格式被前端或存储策略拒绝。
- [ ] 店员不能进入或调用公告管理接口。

## 4. 车辆档案

- [ ] 店员和店长都能按会员查询车辆。
- [ ] 新增首辆车后自动成为默认车辆。
- [ ] 同一会员不能新增重复 `plateKey`。
- [ ] 不同会员可按业务规则拥有相同车牌记录时，唯一约束不误伤跨会员数据。
- [ ] 编辑品牌、车型、颜色、VIN 后版本号递增，旧版本并发保存被拒绝。
- [ ] 切换默认车辆后同一会员仅有一辆默认车。
- [ ] 停用默认车辆后，存在其他启用车辆时自动选择替代默认车。
- [ ] 顾客端只显示自己的启用车辆，不能通过参数读取其他会员车辆。

## 5. 贴膜档案

- [ ] 未选择有效启用车辆时不能保存贴膜档案。
- [ ] 服务日期、类别、品牌、系列、型号、施工位置、质保月数、里程和备注保存正确。
- [ ] 上传 1 张、9 张图片均成功；超过 9 张、错误格式或超限大小被拒绝。
- [ ] 贴膜记录保存车辆快照；后续修改车辆资料不篡改历史快照。
- [ ] 顾客端按时间倒序读取自己的贴膜记录和图片。
- [ ] 旧 `schemaVersion: 1` 记录仍可展示，结构化字段使用兼容默认值。
- [ ] 店员不能为不存在、停用或不属于该会员的车辆创建记录。

## 6. 店员/店长权限

- [ ] 店员可查询会员、充值、消费结算、维护车辆、添加贴膜记录、读取启用消费项目。
- [ ] 店员看不到店长管理入口。
- [ ] 店员直接调用 `adminData`、员工管理、项目管理、公告管理、冲正函数时返回未授权。
- [ ] 店长具备店员业务能力，并可进入店长管理。
- [ ] 未登录请求、伪造 token、空 token 均被拒绝。
- [ ] 顾客身份不能调用员工或店长函数。

## 7. 员工状态、角色与密码

- [ ] 店长新增 `staff` 和 `admin` 两种角色，账号唯一，密码少于 6 位被拒绝。
- [ ] 停用员工后，该员工已有会话立即因状态或 `tokenVersion` 失效，不能继续操作。
- [ ] 重新启用员工后需重新登录。
- [ ] 店员升级为店长后旧会话失效，重新登录后才获得店长权限。
- [ ] 店长降级为店员后旧会话失效，重新登录后不再有店长权限。
- [ ] 修改密码后旧密码不可登录，已有会话失效，新密码可登录。
- [ ] 当前店长不能停用自己或将自己降级。
- [ ] 密码字段在数据库中仅保存 scrypt `salt:hash`，接口和页面不回显哈希。

## 8. 公告与消费项目管理

- [ ] 店长可新增、编辑、排序、启用和停用消费项目。
- [ ] 重名消费项目被函数校验和数据库唯一索引拒绝。
- [ ] 停用项目不出现在店员消费结算下拉框。
- [ ] 已选项目在提交前被停用时，服务端拒绝结算。
- [ ] 并发编辑同一项目时版本冲突可见，不静默覆盖。
- [ ] 店长可新增、编辑、排序、启用和停用公告。
- [ ] 并发编辑同一公告时版本冲突可见，不静默覆盖。

## 9. 充值幂等与并发

- [ ] 正常充值后余额、`balance_logs` 和返回金额一致，全部以整数分保存。
- [ ] 同一 `requestId`、同一参数重复提交只产生一条充值流水，第二次返回 `replayed: true`。
- [ ] 同一 `requestId`、不同金额或支付方式返回 409，不新增流水、不改余额。
- [ ] 两个不同 `requestId` 并发充值时最终余额等于两笔之和，不丢更新。
- [ ] 网络超时后客户端重试原 `requestId` 不会重复加款。
- [ ] 非法金额、非整数分、非法支付方式和禁用会员被拒绝。

## 10. 消费结算幂等与并发

- [ ] 余额足够时仅扣余额，`offlinePaid` 为 0。
- [ ] 余额不足时余额扣至 0，剩余金额记入 `offlinePaid`，线下方式正确。
- [ ] 余额为 0 时全额线下支付，余额不变。
- [ ] 同一 `requestId`、同一参数重复提交只产生一条消费流水。
- [ ] 同一 `requestId`、不同参数返回 409，不重复扣款。
- [ ] 两个不同 `requestId` 并发结算时事务按实际余额顺序计算，最终余额不为负，流水前后余额连续。
- [ ] 充值与消费同时发生时最终余额和流水链条一致。
- [ ] 网络超时重试不重复消费。
- [ ] 已停用消费项目、禁用会员和非法金额被拒绝。

## 11. 冲正与线下退款提示

- [ ] 店长可冲正有效充值流水，原流水 `status` 变为 0，并新增一条 `reversal`。
- [ ] 店长可冲正纯余额消费，余额恢复且新增冲正流水。
- [ ] 混合支付或全额线下支付消费冲正时，只调整系统余额；页面明确显示“线下款需人工处理”。
- [ ] 冲正结果和流水保存 `sourceLogId`、`sourceType`、`balanceDelta`、操作店长及原因。
- [ ] 同一流水不能重复冲正。
- [ ] 已禁用会员、无效流水、冲正流水本身不能被错误处理。
- [ ] 人工线下退款完成后按门店流程留存支付渠道凭证；系统不得虚构自动退款成功。

## 12. 会话过期与退出

- [ ] 正常登录后刷新 H5 可通过 `sessionValidate` 恢复会话。
- [ ] `expireAt` 到期后任意业务调用被拒绝并返回登录页，本地 token 被清除。
- [ ] 员工被停用、角色变化或密码修改后，旧会话下一次校验/调用立即退出。
- [ ] 主动退出后本地 token 被清除，刷新页面不会恢复工作台。
- [ ] 手工篡改 localStorage token 后不能进入工作台。
- [ ] TTL 清理延迟不影响安全：即使过期会话文档尚未被物理删除，服务端仍按 `expireAt` 拒绝。

## 13. 验收收尾

- [ ] 执行 `node scripts/preflight.js` 返回 0，且不再有占位 `envId`、`devMode: true`。
- [ ] 人工确认 H5 `@cloudbase/js-sdk` 已固定为明确可用版本或本地构建产物，不再使用生产 `latest`。
- [ ] 所有云函数依赖均按现有 `package.json` 声明安装并核对；未在部署准备阶段猜测或擅自改写版本。
- [ ] 对测试产生的资金流水只做规范冲正，不直接删除；测试账号和文件按门店数据保留策略清理。
- [ ] 记录未通过项、修复版本和复测结果后，才允许提交小程序审核或开放 H5 正式入口。
